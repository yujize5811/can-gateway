# CAN 双节点网关（CAN-GW v1）

STM32F103CBT6 双节点 CAN 总线通信项目。重点不在「两块板能通信」，而在**位定时算对、多帧传得完、故障能恢复、长跑不丢帧**。

> **本仓库唯一的规则**
> README 和简历里出现的每一个数字，都必须在 `docs/04-pitfalls.md` 或 `docs/records/` 里找到对应的原始记录。
> 没有记录的数字不写。面试官会追问出处，答不上来整个项目就废了。

---

## 1. 硬件

| 物料 | 型号 | 数量 | 说明 |
|---|---|---|---|
| MCU | STM32F103**CBT6** | 2 | 128 KB Flash。买 C8T6 做不了后面的 Bootloader |
| CAN 收发器 | SN65HVD230 | 2 | 3.3 V 器件，与 MCU 电平天然匹配 |
| 终端电阻 | 120 Ω | 2 | 跨接在总线两端，**不是串联** |
| 分析仪 | USB-CAN（PCAN 兼容） | 1 | 旁路抓包，防止自己统计自己 |
| 串口 | CH340 USB-TTL | 1 | 打印日志 |

接线见 [`hardware/wiring.md`](hardware/wiring.md)。

## 2. 架构

```
   节点 A (STM32)                节点 B (STM32)
   ┌──────────┐                 ┌──────────┐
   │ 应用层    │  0x2xx 周期数据  │ 应用层    │
   │ 协议层    │ ───────────────▶│ 协议层    │
   │ bxCAN     │  0x5xx ACK      │ bxCAN     │
   └────┬─────┘ ◀───────────────└────┬─────┘
        │ CANH/CANL                   │
   ┌────┴─────────────────────────────┴─────┐
   │            USB-CAN 分析仪（旁路）        │
   └────────────────────────────────────────┘
```

## 5. 快速复现

```bash
# 1. 装依赖
pip install python-can

# 2. 自检：驱动、接口、设备
python tools/can_check.py

# 3. 抓包到 CSV（默认 PCAN_USBBUS1 @ 500 kbps）
python tools/can_logger.py -t 60 -o run_001.csv

# 4. 分析：帧率、周期抖动、丢帧
python tools/analyze_log.py run_001.csv
```

固件怎么编译、怎么烧，见 [`firmware/README.md`](firmware/README.md)。

## 6. 踩过的坑

完整记录见 [`docs/04-pitfalls.md`](docs/04-pitfalls.md)。目前收录：

1. **CBT6 是被改丝印的 C8T6** —— 读 `0x1FFFF7E0` 只有 64 KB，Bootloader 的 128 KB 分区直接崩
2. **终端电阻接成串联** —— 总线电阻变成无穷大，全部节点通信失败
3. **单板发帧报 `TxError`** —— 不是 bug，是没人回 ACK
4. **用了 TJA1050 接非 FT 引脚** —— 5 V 输出灌进 3.3 V IO

## 7. 已知限制

- 只有 2 个节点，没有验证多主仲裁下的优先级反转
- 72 h 压测在单机环境完成，未做温度循环
- 滑窗协议是自定义的，不是 ISO-TP，不能与第三方设备互通
