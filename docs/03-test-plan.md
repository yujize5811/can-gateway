# 测试计划

每个指标都写清楚：**装置 → 步骤 → 记录什么 → 通过标准**。
测完把结果填进 `README.md` 第 3 节，原始记录放 `docs/records/`。

## 通用装置

```
板 A ──┬──── 板 B
       │
    分析仪（旁路，只收不发）
```

- 分析仪接在总线中间，不占 ID，只做旁路记录
- 所有测试先在室温、5 V USB 供电下完成
- 每次测试前断电量一次 CANH–CANL，**必须 ≈ 60 Ω**

---

## T1 位定时正确性

| 项 | 内容 |
|---|---|
| 装置 | 板 A + 板 B + 示波器接 `CANTX` |
| 步骤 | 发 1 帧，示波器触发在第一位起始沿，量单个位的持续时间 |
| 记录 | 位宽（µs）、分析仪读回的波特率 |
| 通过 | 位宽 2.0 µs ±2 %；分析仪显示 500 kbps；CRC 错误计数 = 0 |

> 只测「两块板能通」不算通过。要单独量波形。

## T2 业务态负载

| 项 | 内容 |
|---|---|
| 步骤 | 板 A 以 20 ms 周期发 `0x201`，跑 60 s |
| 记录 | 总帧数、实际周期均值与抖动（P50/P99）、分析仪算出的总线负载 |
| 通过 | 帧数 ≈ 3000 ±1 %；周期 20 ms ±1 ms；负载 ≈ 1.3 % |

**怎么算负载**：负载 = 每帧总位数 × 帧率 / 波特率。标准帧 8 字节约 111 位（含填充与帧间隔），50 帧/s × 111 / 500 000 ≈ 1.1 %。

## T3 灌包负载上限

| 项 | 内容 |
|---|---|
| 步骤 | 用板 A 以最短间隔连续发，逐步提到 1500 帧/s，跑 60 s |
| 记录 | 实际帧率、分析仪负载百分比、错误帧数、是否 Bus-Off |
| 通过 | 稳定在 ≈40 % 负载不掉帧（这是**压力测试**，不是业务态） |

> README 里写业务负载 1.3 %，不要写 40 %。40 % 是灌包灌出来的，面试官会问「你业务真的跑 40 %？」答不上来就穿帮。

## T4 72 h 长跑

| 项 | 内容 |
|---|---|
| 步骤 | 业务态跑 72 h，板端 `monitor.c` 每秒输出一行 CSV（累计发送/接收/重传/错误） |
| 记录 | 累计帧数、应用层丢帧、Bus-Off 次数、内存剩余 |
| 通过 | 累计 ≈ 1296 万帧、应用层丢帧 0、Bus-Off 0 |

**校验帧数的方法**：20 ms 周期 = 50 帧/s，72 h = 259200 s，50 × 259200 = **12 960 000 帧**（约 1296 万）。

三份数据必须对得上：

1. 板 A `monitor.c` 的发送计数
2. 板 B `monitor.c` 的接收计数
3. 分析仪 CSV 的行数（抽样验证，不要全程抓，文件太大）

三份差一个量级，说明统计代码本身有 bug。

**长跑注意**：

- 串口日志会写满磁盘，用滚动文件或只统计不落盘
- 供电别用电脑 USB，长时间挂机会休眠断连
- 每天手动存一次 `monitor` 累计值，防止程序崩溃丢数据

## T5 多帧传输

| 项 | 内容 |
|---|---|
| 步骤 | 传 1 KB 随机数据 100 次 |
| 记录 | 成功次数、平均耗时、重传次数 |
| 通过 | 成功 100/100，CRC32 全部校验通过 |

## T6 停等 vs 滑窗

| 项 | 内容 |
|---|---|
| 步骤 | 同一份 1 KB 数据，分别用 v1 停等、v2 滑窗传 10 次，取平均 |
| 记录 | 两种模式的耗时、吞吐 |
| 通过 | 滑窗耗时 ≈ 停等的 1/5（8.6 s → 1.7 s） |

## T7 Bus-Off 恢复

| 项 | 内容 |
|---|---|
| 步骤 | 用分析仪或外部设备强注入错误帧（连续 TEC 溢出），触发 Bus-Off |
| 记录 | 记录 BOFF 位被置位的时刻，到恢复正常收发的耗时 |
| 通过 | < 200 ms 自动恢复，不需要断电重启 |

**实现方式**：检测到 `CAN_ESR` 的 BOFF 位后，清 `CAN_MCR.INRQ` 重新初始化，比自动恢复（ABOM）更可控。

## T8 离线判定

| 项 | 内容 |
|---|---|
| 步骤 | 跑着的时候拔掉板 B 的电源 5 s，再插回 |
| 记录 | 网关从最后一次收到心跳到判离线的时长；恢复后重新上线的时长 |
| 通过 | 3 s 判离线（3 个周期），2 s 内上线 |

## T9 实时性

| 项 | 内容 |
|---|---|
| 步骤 | 中断入口翻转一个 GPIO，任务处理完再翻转一次，示波器量两沿间隔 |
| 记录 | 至少 1000 次的分布，取 P50 / P99 / max |
| 通过 | P99 < 500 µs |

## 记录格式

每次测试在 `docs/records/` 建一个文件，命名 `YYYYMMDD-测试编号.md`：

```markdown
# T4 72h 长跑

- 日期：2026-11-__
- 固件 commit：a1b2c3d
- 环境：室温 18 ℃，USB 5 V 供电

## 原始数据
（monitor 累计值、分析仪抽样行数、异常记录）

## 结论
通过 / 不通过，与目标的差距，原因分析
```

CSV 原始文件不入库（太大），只把**摘要和结论**写进 md。需要原始数据时存在本地。
