# 位定时计算：500 kbps @ 36 MHz

这份文档是整个项目里最容易被面试官追问、也最能证明「你真的懂」的地方。所有数字都可以自己复算。

## 0. 结论

| 参数 | 值 | 说明 |
|---|---|---|
| CAN 时钟 PCLK | 36 MHz | APB1 = 72 MHz 二分频 |
| BRP（分频） | 8 | 寄存器写入 `BRP-1 = 7` |
| tq | 222.2 ns | 一个时间份额 |
| 每位 tq 数 | 9 | Sync + BS1 + BS2 |
| 位时间 | 2 µs | 9 × 222.2 ns |
| 段划分 | Sync=1, BS1=6, BS2=2 | |
| 采样点 | 77.8 % | (1+6)/9 |
| SJW | 1 | 只在多节点时钟有偏差时才需要加大 |
| BTR 寄存器 | `0x00150007` | 建议写死，不信 CubeMX 默认值 |

## 1. 三个公式，缺一不可

```
tq      = BRP / PCLK
位时间  = (1 + BS1 + BS2) × tq
波特率  = 1 / 位时间
```

采样点位置：

```
采样点 = (1 + BS1) / (1 + BS1 + BS2)
```

三个数必须互相闭合：**算出位时间，反推波特率，必须正好等于目标值**。差一位都不行。

## 2. 正推一遍

要求 500 kbps：

```
位时间 = 1 / 500 kbps = 2 µs
```

选 BRP = 8：

```
tq = 8 / 36 MHz = 222.2 ns
9 × 222.2 ns = 2.0 µs  ✓
```

9 个 tq 怎么分：

- Sync = 1 tq（固定，用于硬同步）
- BS1 = 6 tq（传播段 + 相位缓冲段 1）
- BS2 = 2 tq（相位缓冲段 2）

采样点在 BS1 结束、BS2 开始之间：

```
(1 + 6) / 9 = 77.8 %
```

落在 CAN 推荐的 75 %–87.5 % 区间内。

## 3. 反例：BRP=4 为什么是错的

原方案取 BRP=4，看数字「4 × 9 = 36，36 MHz / 36 = 1 MHz」像是自洽的，但：

```
tq = 4 / 36 MHz = 111.1 ns
9 × 111.1 ns = 1.0 µs
波特率 = 1 / 1 µs = 1 Mbps
```

**得到的是 1 Mbps，不是 500 kbps。**

这个错误特别迷惑人，因为：

- 单板自环回环测试**能发出去**（自发自收不校验真实时序）
- 只插一块板时看不到任何报错
- 一旦接上第二块板，就是大量错误帧、CRC 错、Bus-Off

**判断方法**：接两块板之前，先用分析仪读回它识别到的波特率。分析仪显示 1 Mbps 而代码里写 500 kbps，就是这里错了。

## 4. 采样点为什么不能随便取

采样点太靠前（< 70 %）：信号还没稳定就采样，长线缆上误码率飙升。
采样点太靠后（> 90 %）：留给 BS2 的相位缓冲太短，时钟偏差没空间调整。

经验值：

| 场景 | 推荐采样点 |
|---|---|
| 通用 | 75 %–80 % |
| 长线 / 多节点 | 80 %–87.5 % |
| CANopen / 工业 | 87.5 % |

本项目取 77.8 %。

## 5. 怎么验证算对了

三条独立证据，缺一不可：

1. **示波器**：量 `CANTX` 引脚上一位的宽度，应为 2 µs。这是最直接的证据。
2. **分析仪读回**：分析仪识别到的波特率必须是 500 kbps，丢帧率接近 0。
3. **双板互通**：两块板互发，CRC 错误计数为 0。

只做第 3 条不够——两块板都错成 1 Mbps 时，第 3 条也是通的。

## 6. 寄存器对照（STM32 bxCAN）

`CAN_BTR` 布局：

| 位 | 名称 | 含义 | 本项目取值 |
|---|---|---|---|
| 25:24 | SJW | 重同步跳宽 | `SJW-1 = 0` |
| 22:20 | TS2 | BS2 | `TS2-1 = 1` |
| 19:16 | TS1 | BS1 | `TS1-1 = 5` |
| 9:0 | BRP | 分频 | `BRP-1 = 7` |

合起来：

```
0x00150007 = 0b0000_0000_0001_0101_0000_0000_0000_0111
```

配好之后**回读 `CAN->BTR` 确认**，不要假设 HAL 写进去的就是你想的。

## 7. 换主频怎么办

如果 APB1 不是 36 MHz（比如降到 24 MHz），公式不变，重新选 BRP：

```
BRP = PCLK × 位时间 / 9
```

24 MHz 时：`BRP = 24e6 × 2e-6 / 9 = 5.33` —— 不是整数，说明 24 MHz 下做不出精确的 500 kbps，只能取 5（540 kbps）或 6（444 kbps），误差都超标。

**结论：F103 跑 500 kbps 必须让 APB1 = 36 MHz。** 这也是为什么不能随便改主频。
