# 双节点互发

- 日期：2026-11-09
- 对应指标：T2 业务负载（链路连通性）
- 固件 commit：待补

## 1. 我预期发生什么

两块 F103CBT6 挂在同一条 500 kbps 总线上，A 发 `0x201`、B 发 `0x202`，各自 20 ms 周期。
两块板都能收到对方的帧，PCAN-View 同时看到两条 ID，接收计数同步增长。

## 2. 实际发生了什么

```
201h   8  74 05 52 00 00 00 00 00   21.0 ms   Count 1397
202h   8  51 03 51 00 00 00 00 00   20.9 ms   Count 850
```

数据格式：`[0][1]` = 本节点发送计数（小端），`[2]` = 已收到的对方帧数。

- A 发送计数 `0x0574` = 1396，PCAN 收到 1397 帧，对得上
- B 发送计数 `0x0351` = 849，PCAN 收到 850 帧，对得上
- A 收到 B 的帧：`0x52` = 82
- B 收到 A 的帧：`0x51` = 81

## 3. 差在哪

没有差。

两个接收计数相差 1，是两块板上电时刻不同造成的：后上电的那块在对方已经跑了一会儿之后才开始数。
继续观察时两个数同步增长，差 1 保持不变，说明没有丢帧。

周期 21.0 / 20.9 ms 的抖动来自 `HAL_Delay()` 的 1 ms 量化，与单节点实测一致。

## 4. 结论·下一步

**双向通信成立**：总线上有两个节点，各自周期发送、各自接收对方，ACK 正常，仲裁无冲突。

下一步：CAN-GW v1 协议层——ID 分段（0x1xx 心跳 / 0x2xx 数据 / 0x3xx 命令 / 0x4xx 多帧 / 0x5xx ACK）、
帧头加类型与序号、CRC8 校验。
