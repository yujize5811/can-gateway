# 业务帧率实测

- 日期：2026-11-04
- 对应指标：T2 业务态帧率与总线负载
- 固件 commit：见 MDK-ARM/can_gw（StdId 0x201，DLC 8，HAL_Delay(20)）

## 1. 我预期发生什么

每 20 ms 发一帧 0x201，即 50 帧/秒，总线负载约 1.3%。

## 2. 实际发生了什么

PCAN-View 实测：

| 项目 | 读数 |
|---|---|
| Cycle Time | 21.0 ms |
| Count | 1529 帧 |
| Data | F8 05 00 00 00 00 00 00（cnt = 0x05F8 = 1528） |

换算：1000 / 21.0 = 47.6 帧/秒。
总线负载：47.6 × 108 bit / 500000 ≈ 1.03%（按标准帧 108 位计）。

## 3. 差在哪

没有功能性偏差，差 5% 来自 `HAL_Delay` 的量化：

- `HAL_GetTick()` 是 1 ms 粒度，`HAL_Delay(20)` 实际等待 20~21 ms；
- 叠加循环开销（AddTxMessage + 计数器）几十微秒；
- 结论：21.0 ms 属预期行为，不影响业务。

## 4. 结论·下一步

- 单节点发帧链路打通，速率稳定，无丢帧。
- 若要精确 20.00 ms，需改用定时器中断触发发送，不用 HAL_Delay。列入后续优化，不阻塞主线。
- 下一步：第二块板改为 0x202，双节点互发。
