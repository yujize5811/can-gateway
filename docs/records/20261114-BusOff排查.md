# Bus-Off 检测排查

- 日期：2026-11-14
- 对应指标：T7 Bus-Off 注入与恢复
- 固件 commit：本批提交（诊断版：心跳 `payload[2]` 临时放 TEC）

## 1. 我预期发生什么

把 A 板的 ACK 来源全部拿掉（B 断电 + 分析仪不出 ACK），A 发出去的帧没人应答：

- 每帧发送错误计数 TEC +8
- 32 帧后 TEC 超过 255，进入 Bus-Off（20 ms 一帧，约 **0.64 秒**）
- `AutoBusOff = DISABLE` 时 BOFF 位保持为 1，20 ms 一次的主循环能读到
- 读到后 `busOffCnt++`，并调用 `HAL_CAN_Start()` 把控制器拉回正常模式

预期心跳第 3 字节能看到 TEC 冲到 255，第 4 字节 `busOffCnt` 开始增长。

## 2. 实际发生了什么

### 实验一：短接 CANH–CANL（失败）

短接瞬间三个收发器同时输出对立电平，电流大，USB 口电压跌落，给 B 板供电的 ST-Link 掉线，B 断电重启。

证据：`202h` 的 `cnt = 118`，而 A 是 `11622` —— B 只跑了 2.5 秒的量。

结论：短接法在这套供电结构（B 由 ST-Link 供电）上不可用。

### 实验二：拔 RX（无效）

拔掉模块的 `RX`（接 `PA11`）只影响接收，发送照常：`201h` 照常、`cnt` 照常涨。

唯一的判据应该是 **`201h` 从 PCAN-View 消失**，而不是"拔了根线"。

### 实验三：Listen-only 隔离（成功）

PCAN-View → `Connect` → `Options` → 勾 `Listen-only mode`：分析仪变成只收不发的录音机，不再替总线上任何帧回 ACK。

隔离期间：

```
201h   Count 涨到 886719，Cycle Time 0.3 ms   ← 重发风暴
101h   Count 冻结，up = 16 s                  ← 心跳帧卡在发送邮箱里，一直被重发
202h   Count 冻结在 143                        ← B 已下线
```

886719 ÷ 600 秒 ≈ **1477 帧/秒**，与"每 20 ms 被恢复一次、每次重发约 32 帧（1600 帧/秒）"吻合。

### 恢复 ACK 之后

```
101h   10 21  8E 00 00 00 00  04    up=142 s  TEC=0  busOff=0  status=0x00
201h   21 D9  01 7C 00 00 81        cnt=473   lost=124  status=0x00
```

`up` 从冻结的 16 s 涨到 142 s、`status` 从 `0x80` 回到 `0x00` —— **节点活着，没有卡死在 Bus-Off 里**。

但 `busOffCnt` 仍然是 **0**。

## 3. 差在哪

- **现象**：重发风暴证明帧确实没被 ACK（否则不会重发），但 `busOffCnt` 从未增长，BOFF 位像从来没被读到过。
- **排查过程**（逐一排除）：
  1. 怀疑固件是旧版本 → `can.c:47` 是 `hcan.Init.AutoBusOff = DISABLE;`，`can.o` 与 `.axf` 时间戳同为 18:16:33 → 排除
  2. 怀疑位定义写错 → CMSIS `stm32f103xb.h:5818` 定义 `CAN_ESR_BOFF_Pos = 2U`，代码 `(CAN1->ESR >> 2) & 1u` 正确 → 排除
  3. 怀疑变量被局部变量遮蔽 → `main.c:154-156` 三个变量无同名局部 → 排除
  4. 怀疑轮询采样不到 → `ABOM` 开启时 Bus-Off 后 0.28 ms 就自动恢复、BOFF 位只维持瞬间，20 ms 轮询必然漏；但 `ABOM` 已经改成 `DISABLE`，按理 BOFF 位应保持
- **根因**：**未定位**。目前只剩两种可能：①这段边沿检测代码没有被执行到；②`ESR` 的 BOFF 位在别处被清掉。
- **代价**：一整天，四次烧写，两次实验失败（一次烧掉 USB 供电、一次拔错线）。

## 4. 结论·下一步

已经拿到、且确定可靠的三条：

1. **只要 PCAN-View 以 Normal 模式连着总线，它会替总线上所有节点回 ACK**，单节点永远进不了 Bus-Off。做总线故障实验必须切 `Listen-only`。
2. **短接总线会因电流过大把 USB 供电拉垮**；开路（拔 CANH 或 CANL）才是标准做法，电流几乎为零。
3. **ABOM 开启时 BOFF 位只维持几百微秒**，软件轮询几乎必然漏采 —— 要么关 ABOM，要么把这个检测改成中断方式。

下一步：不再靠"改代码 → 烧录 → 看结果"的盲循环，改用 **Keil 在线调试**：

- `Ctrl+F5` 进调试
- 在 `busOffNow = (CAN1->ESR >> 2) & 1u;` 下断点
- Watch 窗口加 `CAN1->ESR`、`CAN1->MCR`
- 拔 B + Listen-only，让 A 失败
- 看断点停不停、`ESR` bit2 是不是 1、`MCR` bit6（ABOM）是不是 0

一屏数据就能区分"代码没执行"和"硬件没置位"。
